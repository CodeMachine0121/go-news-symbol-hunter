# 標的名稱 — Requirements Brief

## Goal
目前分析結果與追蹤標的評等只顯示標的代號（如 2330、AAPL、BTC），使用者要自己記代號對應哪一家公司或哪一種幣。本功能替標的加上「標的名稱」（如 2330 → 台積電），讓使用者看結果時直接看到名字。追蹤標的的名稱由 administrator 自行登記；使用者發起的分析，名稱由系統在分析前辨識標的時自動帶入並保存。名稱只用來保存與顯示，不影響新聞搜尋與分析本身。

## Requirements
- **追蹤標的的名稱**
  - 每個追蹤標的可以有一個名稱，由 administrator 直接維護（比照追蹤標的清單本身的做法），不提供管理功能。
  - 名稱可以不填；沒填時，查詢結果的名稱為空。
  - 使用者查詢追蹤標的評等時，每個追蹤標的的結果都附上它目前登記的名稱。
  - 名稱不影響自動分析：自動分析仍照原本方式辨識標的、搜尋新聞。
- **使用者發起的分析的名稱**
  - 使用者發起分析時，仍然只提供標的與市場類別，不需要、也不能提供名稱。
  - 系統在發起分析、辨識標的時取得名稱，保存在這次分析事件與它的分析結果上：
    - 台股：公司簡稱（與目前搜尋新聞用的公司簡稱相同，如「台積電」）。
    - 加密貨幣：幣種名稱（與目前搜尋新聞用的幣種名稱相同，如「Bitcoin」）。
    - 美股：向美股報價來源查詢公司名稱（英文，如「Apple Inc.」）。
  - 美股名稱查不到（報價來源暫時無法使用、或沒有提供名稱）時，名稱為空，分析照常進行；不因名稱而拒絕或失敗。美股標的是否存在的判斷維持現狀（不因此新增拒絕）。
  - 查詢分析事件時，分析事件與分析結果都附上名稱。
  - 發起分析時沿用既有的分析事件（重用時間窗內）時，回傳的是那筆既有分析事件原本保存的名稱，不以這次查到的名稱覆蓋。
- **名稱與搜尋字分開**
  - 名稱只用於保存與顯示；新聞搜尋使用的搜尋字規則完全不變（美股仍以標的代號搜尋）。
- **既有資料**
  - 功能上線前就存在的追蹤標的、分析事件、分析結果，名稱為空，不回頭補。

## Examples (Specification by Example)
Each example lists **only** the data that affects the behavior — nothing more.

### Rule: 追蹤標的評等附上 administrator 登記的名稱
| # | Given (only relevant data) | When | Then |
|---|---|---|---|
| 1 (happy) | 追蹤標的 2330 / 台股，名稱登記為「台積電」，今天有綜合評等 | 使用者查詢追蹤標的評等 | 2330 的結果附上名稱「台積電」 |
| 2 (boundary) | 追蹤標的 2317 / 台股，名稱沒填，今天有綜合評等 | 使用者查詢追蹤標的評等 | 2317 的結果照常回傳，名稱為空 |
| 3 (exception) | 追蹤標的 2330 名稱登記為「台積」（與公司簡稱「台積電」不同） | 盤前自動分析 2330 | 仍以公司簡稱「台積電」搜尋新聞；查詢時名稱顯示「台積」 |
| 4 (happy) | 2330 名稱原為空，administrator 改登記為「台積電」 | 使用者再次查詢追蹤標的評等 | 結果名稱顯示「台積電」（以查詢當下登記的名稱為準） |

### Rule: 使用者發起的分析自動帶入名稱
| # | Given (only relevant data) | When | Then |
|---|---|---|---|
| 1 (happy) | 2330 / 台股，公司簡稱「台積電」 | 使用者發起分析，之後查詢該分析事件 | 分析事件與分析結果的名稱都是「台積電」 |
| 2 (happy) | BTC / 加密貨幣，幣種名稱「Bitcoin」 | 使用者發起分析 | 名稱為「Bitcoin」 |
| 3 (happy) | AAPL / 美股，報價來源提供公司名稱「Apple Inc.」 | 使用者發起分析 | 名稱為「Apple Inc.」；新聞仍以「AAPL」搜尋 |
| 4 (exception) | AAPL / 美股，報價來源暫時查不到資料 | 使用者發起分析 | 分析照常進行，名稱為空 |
| 5 (exception) | ZZZZ / 美股，報價來源查無此代號 | 使用者發起分析 | 與現在一樣照常分析（不拒絕），名稱為空 |
| 6 (exception) | 9999 / 台股，上市與上櫃清單都查不到 | 使用者發起分析 | 與現在一樣拒絕（標的不存在），不會產生分析 |
| 7 (boundary) | 2330 / 台股，3 小時前已有一筆完成的分析，當時名稱為「台積電」 | 使用者再次發起分析 | 回傳那筆既有分析，名稱為「台積電」，不重新分析 |
| 8 (exception) | 某次分析沒有完成（分析失敗） | 使用者查詢該分析事件 | 分析事件仍附上名稱；沒有分析結果 |

### Rule: 既有資料不回補
| # | Given (only relevant data) | When | Then |
|---|---|---|---|
| 1 (boundary) | 本功能開始使用前發起的 2330 分析事件 | 使用者查詢該分析事件 | 名稱為空 |
| 2 (happy) | 本功能開始使用後才發起的 2330 分析 | 使用者查詢該分析事件 | 名稱為「台積電」 |

## Out of Scope
- 由使用者提供或修改分析的名稱。
- 管理追蹤標的（含名稱）的功能。
- 名稱的翻譯或統一（美股為英文名稱，不翻成中文）。
- 回頭補齊既有資料的名稱。
- 評等回測、搜尋標的新聞的結果顯示名稱。
- 自動分析的時段評等、綜合評等另外保存名稱（查詢時以追蹤標的目前登記的名稱為準）。

## Open Decisions
Items the PRD author should resolve:
- 名稱最大長度。
- 名稱為空時對外呈現方式（空字串或省略）。
- 查詢美股名稱的等待上限，避免拖慢發起分析。

## Context / Background
- 名稱來源與使用者討論確定：追蹤標的由 administrator 手動填；使用者發起的分析由系統自動帶入，不開放使用者提供名稱。
- 台股公司簡稱與加密貨幣幣種名稱，系統在辨識標的時本來就會取得，目前只用於搜尋新聞而未保存。美股報價來源（取分析時價格的同一來源）的回應本來就含公司名稱，只是沒有使用。
- 前端操作台會另開對應功能切片，顯示這個名稱。
- 流程規模（Jev：medium）：clarify → prd → architecture → implement（code-first）→ improve-codebase → contract。開放問題一律採 best practice 自行決定。
