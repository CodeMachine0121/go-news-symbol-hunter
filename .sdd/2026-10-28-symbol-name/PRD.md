# Product Requirements Document (PRD) — 標的名稱

**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:** 分析事件、分析結果與追蹤標的評等只顯示標的代號（2330、AAPL、BTC）。使用者看結果時要自己記代號對應哪一家公司或哪一種幣；台股代號尤其難記。系統其實在辨識標的時就已取得台股公司簡稱與加密貨幣幣種名稱，只是用完即丟。
- **Expected Outcome:**
  - 使用者查詢追蹤標的評等時，每個追蹤標的都附上 administrator 登記的標的名稱。
  - 本功能開始使用後發起的每一筆分析，查詢時分析事件與分析結果都附上標的名稱：台股為公司簡稱、加密貨幣為幣種名稱、美股為公司英文名稱（查得到時）。
  - 新聞搜尋、評等、重用規則、自動分析等既有行為完全不變。
- **Out of Scope:**
  - 使用者提供或修改分析的標的名稱。
  - 管理追蹤標的（含標的名稱）的功能。
  - 標的名稱的翻譯或統一（美股維持英文，不翻成中文）。
  - 回頭補齊既有資料的標的名稱。
  - 評等回測、搜尋標的新聞的結果顯示標的名稱。
  - 時段評等、綜合評等另外保存標的名稱。

---

## 2. User Personas

- **Primary Role(s):**
  - Administrator：直接登記追蹤標的的標的名稱。
  - 持有已啟用 API key 的使用者（含前端操作台）：發起分析、查詢分析事件、查詢追蹤標的評等。
- **Usage Context:** 使用者在操作台或以程式查看分析事件與追蹤標的評等時，直接看到標的名稱，不必自行對照代號。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 追蹤標的評等附上標的名稱 [priority: P0]
**As a** 持有已啟用 API key 的使用者, **I want** 追蹤標的評等附上 administrator 登記的標的名稱, **so that** 我不用自己記代號是哪一家公司。

```gherkin
Scenario: 有登記標的名稱的追蹤標的
  Given 追蹤標的 2330 / 台股 的標的名稱登記為「台積電」
  And 2330 今天有綜合評等
  When 使用者查詢追蹤標的評等
  Then 2330 的結果附上標的名稱「台積電」

Scenario: 沒有登記標的名稱的追蹤標的
  Given 追蹤標的 2317 / 台股 沒有登記標的名稱
  And 2317 今天有綜合評等
  When 使用者查詢追蹤標的評等
  Then 2317 的結果照常回傳
  And 2317 的標的名稱為空

Scenario: 登記的標的名稱不影響自動分析的搜尋字
  Given 追蹤標的 2330 / 台股 的標的名稱登記為「台積」
  And 2330 的公司簡稱為「台積電」
  When 盤前自動分析 2330
  Then 以「台積電」搜尋新聞
  And 使用者查詢追蹤標的評等時，2330 的標的名稱為「台積」

Scenario: 以查詢當下登記的標的名稱為準
  Given 追蹤標的 2330 / 台股 原本沒有登記標的名稱，今天有綜合評等
  And administrator 之後把 2330 的標的名稱登記為「台積電」
  When 使用者再次查詢追蹤標的評等
  Then 2330 的標的名稱為「台積電」
```

### US-02 — 使用者發起的分析自動帶入標的名稱 [priority: P0]
**As a** 持有已啟用 API key 的使用者, **I want** 我發起的分析自動帶上標的名稱, **so that** 查詢分析事件時一眼看出分析的是哪個標的。

```gherkin
Scenario: 台股以公司簡稱為標的名稱
  Given 2330 / 台股 的公司簡稱為「台積電」
  When 使用者發起分析，之後查詢該分析事件
  Then 分析事件的標的名稱為「台積電」
  And 分析完成後，分析結果的標的名稱也為「台積電」

Scenario: 加密貨幣以幣種名稱為標的名稱
  Given BTC / 加密貨幣 的幣種名稱為「Bitcoin」
  When 使用者發起分析
  Then 分析事件的標的名稱為「Bitcoin」

Scenario: 美股以報價來源提供的公司名稱為標的名稱
  Given AAPL / 美股 在美股報價來源的公司名稱為「Apple Inc.」
  When 使用者發起分析
  Then 分析事件的標的名稱為「Apple Inc.」
  And 新聞仍以「AAPL」搜尋

Scenario: 美股報價來源暫時查不到資料
  Given AAPL / 美股
  And 美股報價來源暫時查不到資料
  When 使用者發起分析
  Then 分析照常發起並執行
  And 分析事件的標的名稱為空

Scenario: 美股報價來源查無此代號
  Given ZZZZ / 美股
  And 美股報價來源查無此代號
  When 使用者發起分析
  Then 分析照常發起並執行（與現在一樣不拒絕）
  And 分析事件的標的名稱為空

Scenario: 台股查無此標的仍然拒絕
  Given 9999 / 台股 在上市與上櫃清單都查不到
  When 使用者發起分析
  Then 分析被拒絕，原因為標的不存在
  And 不會產生分析事件

Scenario: 重用既有分析時沿用原本的標的名稱
  Given 2330 / 台股 3 小時前已有一筆完成的分析事件，標的名稱為「台積電」
  When 使用者再次發起 2330 / 台股 的分析
  Then 回傳那筆既有分析事件，標的名稱為「台積電」
  And 不重新分析

Scenario: 分析失敗仍附上標的名稱
  Given 2330 / 台股 的一筆分析事件已失敗，標的名稱為「台積電」
  When 使用者查詢該分析事件
  Then 分析事件的標的名稱為「台積電」
  And 沒有分析結果
```

### US-03 — 既有資料不回補 [priority: P1]
**As a** administrator, **I want** 既有資料維持原狀, **so that** 上線不需要額外整理資料。

```gherkin
Scenario: 本功能開始使用前發起的分析
  Given 一筆本功能開始使用前發起的 2330 / 台股 分析事件
  When 使用者查詢該分析事件
  Then 分析事件照常回傳
  And 標的名稱為空

Scenario: 本功能開始使用後發起的分析
  Given 一筆本功能開始使用後才發起的 2330 / 台股 分析事件
  When 使用者查詢該分析事件
  Then 標的名稱為「台積電」
```

## 4. Business Flow & Logic

- **Flow:** 使用者發起分析 → 驗證並辨識標的（同時取得標的名稱）→ 重用既有分析事件（沿用其標的名稱），或建立新的分析事件並保存這次取得的標的名稱 → 背景執行分析 → 分析完成時，分析結果保存與分析事件相同的標的名稱。
- **Core Business Rules:**
  - 標的名稱來源：
    - 追蹤標的：administrator 登記，可為空。
    - 使用者發起的分析：台股為公司簡稱（上市優先、其次上櫃，與辨識標的相同）；加密貨幣為幣種名稱（與辨識標的相同）；美股為美股報價來源提供的公司名稱。
  - 標的名稱只用於保存與顯示，不改變搜尋字（美股仍以標的代號搜尋）。
  - 標的名稱最長 100 個字；系統自動取得的標的名稱超過時只保留前 100 個字，前後空白去除。
  - 分析結果的標的名稱與所屬分析事件相同。
  - 追蹤標的評等的標的名稱以查詢當下 administrator 登記的為準。
- **Edge Cases:**
  - 美股報價來源無法連線、逾時或沒有提供名稱 → 標的名稱為空，分析照常進行，不記為失敗。
  - 美股報價來源查無代號 → 不拒絕分析（美股是否存在的判斷維持現狀）。
  - 重用既有分析事件 → 沿用其原本的標的名稱，不覆蓋。
  - 既有資料 → 標的名稱為空，不回補。

## 6. Non-Functional Requirements

- **Performance:** 查詢美股公司名稱最多等待 5 秒；超過即視為查不到，標的名稱為空，不拖慢發起分析超過此上限。
- **Security:** N/A（沿用既有 API key 保護）。
- **Compatibility:** 既有呼叫方式不變；回應只新增標的名稱，既有內容不變。
- **Analytics / Tracking:** N/A。

---

## 7. Dependencies & Risks

- **External Dependencies:** 美股報價來源（與取得分析時價格為同一來源）提供公司名稱；證交所、櫃買中心、幣種清單（既有）。
- **Known Risks:** 美股報價來源為非官方服務，可能變更或停止提供名稱——此時美股標的名稱為空，不影響分析。
