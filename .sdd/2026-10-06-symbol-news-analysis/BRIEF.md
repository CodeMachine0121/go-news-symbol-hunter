# 標的資訊面分析 — Requirements Brief

## Goal
讓持有已啟用 API key 的使用者，提供標的與市場類別即可發起一次 AI 資訊面分析。AI 自行使用「搜尋標的新聞」能力取得近期新聞，產出標準化的分析結果：評等、信心指數、時間範圍、理由、關鍵事件、風險因子。每次分析都記錄成一筆分析事件，使用者以分析事件編號查詢進度與結果。同一標的短時間內重複分析時直接重用既有結果，控制 AI 成本。

## Requirements
- 只有持有「已啟用且未撤銷」API key 的使用者可以發起分析與查詢分析事件。
- 發起分析需提供標的與市場類別，規則同標的新聞搜尋（市場類別三選一、標的必填、找不到標的即拒絕）；這些檢查在發起當下完成，不建立分析事件。
- 發起成功後立即回傳分析事件編號與狀態「分析中」；分析在背景進行。
- 分析事件狀態：分析中 → 已完成 / 失敗。失敗時記錄失敗原因。
- 使用者以分析事件編號查詢：分析中只看到狀態；已完成看到分析結果；失敗看到失敗原因。不存在的編號 → 告知找不到此分析事件。
- 分析事件不限發起者，任何已啟用的 API key 都可查詢（分析的是公開市場資訊）。
- 重用：同一標的（同市場類別）在 6 小時內已有「已完成」的分析事件 → 直接回傳該分析事件，不重新分析；若有「分析中」的分析事件 → 回傳該分析事件，不重複發起。
- AI 透過「搜尋標的新聞」取得新聞，可另外搜尋相關標的（例如同產業公司），一次分析最多 5 輪工具使用；超過仍未給出結論 → 分析失敗。
- 分析結果欄位：
  - 評等：強烈看多 / 看多 / 中性 / 看空 / 強烈看空；AI 給出其他值 → 中性。
  - 信心指數：0–100 的整數；超出範圍 → 夾到 0 或 100。
  - 時間範圍：短期（兩週內）/ 中期（三個月內）；其他值 → 短期。
  - 理由：文字，必填；AI 未給 → 分析失敗。
  - 關鍵事件：最多 5 則，每則包含標題、連結、發布時間，**必須是 AI 這次實際取得的新聞**；不是的略過，超過 5 則只留前 5 則。
  - 風險因子：最多 5 條文字。
  - 分析佐證：AI 這次取得的所有新聞（標題、連結、發布時間、新聞來源名稱），供日後稽核。
- 這次分析完全沒有取得任何新聞 → 評等一律中性、信心指數 0。
- 服務重新啟動時，仍為「分析中」的分析事件改為失敗，原因「服務重新啟動，分析中斷」。

## Examples (Specification by Example)

### Rule: 發起分析
| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 已啟用 API key；BTC 近 6 小時沒有分析 | 發起 BTC / 加密貨幣分析 | 取得新的分析事件編號，狀態分析中 |
| 2 (exception) | 市場類別「港股」 | 發起分析 | 被拒，告知市場類別只能是 crypto、twStock、usStock；不建立分析事件 |
| 3 (exception) | 標的 9999 / 台股，不在上市公司清單 | 發起分析 | 被拒，告知找不到此標的；不建立分析事件 |
| 4 (exception) | 停用中的 API key | 發起分析 | 被拒，告知 API key 尚未啟用 |

### Rule: 重用既有分析
| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | BTC / 加密貨幣 5 小時 59 分前完成一次分析 | 發起 BTC 分析 | 回傳那次的分析事件，不重新分析 |
| 2 (boundary) | BTC 6 小時 1 分前完成一次分析 | 發起 BTC 分析 | 建立新的分析事件 |
| 3 (boundary) | BTC 有一筆分析中的分析事件 | 發起 BTC 分析 | 回傳分析中的那筆，不重複發起 |
| 4 (boundary) | BTC 1 小時前分析失敗 | 發起 BTC 分析 | 建立新的分析事件 |
| 5 (boundary) | BTC / 加密貨幣 1 小時前完成；查詢 BTC / 美股 | 發起 BTC / 美股分析 | 建立新的分析事件（不同市場類別不重用） |

### Rule: 查詢分析事件
| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 分析事件已完成 | 查詢 | 看到狀態已完成與完整分析結果 |
| 2 (happy) | 分析事件分析中 | 查詢 | 看到狀態分析中，沒有分析結果 |
| 3 (exception) | 分析事件失敗，原因 AI 服務暫時無法使用 | 查詢 | 看到狀態失敗與失敗原因 |
| 4 (exception) | 編號不存在 | 查詢 | 被拒，告知找不到此分析事件 |
| 5 (happy) | 分析事件由另一把 API key 發起 | 以自己已啟用的 API key 查詢 | 看到該分析事件 |

### Rule: 分析結果正規化
| # | Given | When | Then |
|---|---|---|---|
| 1 (exception) | AI 評等給「超級看多」 | 分析完成 | 評等為中性 |
| 2 (boundary) | AI 信心指數 130 / -5 | 分析完成 | 信心指數 100 / 0 |
| 3 (exception) | AI 時間範圍給「長期」 | 分析完成 | 時間範圍為短期 |
| 4 (exception) | AI 的關鍵事件中有一則連結不在這次取得的新聞裡 | 分析完成 | 該則被略過 |
| 5 (boundary) | AI 給 7 則有效關鍵事件 / 7 條風險因子 | 分析完成 | 只保留前 5 則 / 前 5 條 |
| 6 (boundary) | 這次沒有取得任何新聞，AI 給看多 80 | 分析完成 | 評等中性、信心指數 0 |
| 7 (exception) | AI 沒有給理由 | 分析結束 | 分析失敗，原因「AI 未提供完整分析」 |

### Rule: 分析失敗
| # | Given | When | Then |
|---|---|---|---|
| 1 (exception) | AI 服務無法使用 | 分析進行中 | 分析事件失敗，原因「AI 服務暫時無法使用」 |
| 2 (exception) | AI 用完 5 輪工具仍未給出結論 | 分析進行中 | 分析事件失敗，原因「AI 未在限制內完成分析」 |
| 3 (exception) | 分析中時服務重新啟動 | 服務啟動 | 分析事件失敗，原因「服務重新啟動，分析中斷」 |

## Out of Scope
- 分析時價格與回測（下一個切片）。
- 定時自動分析。
- 分析事件列表、依標的查詢歷史分析。
- 取消分析。

## Open Decisions
- AI 模型與思考深度。
- 一次分析的 AI 用量記錄方式。

## Context / Background
- 使用者決策：資料只存分析事件與分析結果兩種紀錄（另有 API key）。
- 評等以「資訊面」為範圍，不做技術面 / 籌碼面。
