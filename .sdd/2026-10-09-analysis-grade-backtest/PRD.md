# Product Requirements Document (PRD) — 分析評等回測

**Status:** Draft
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:** 專案的成功指標是「使用者發起的分析，評等可回測驗證，且命中率需優於隨機」。目前每筆分析都有評等，卻沒有辦法回頭看「當時說會漲，後來到底有沒有漲」，成功指標無從驗證。
- **Expected Outcome:**
  - 使用者可以查詢一份命中率總表，看出評等方向的命中率是否高於隨機猜測（50%）。
  - 命中率可依市場類別、評等、信心分組拆開看，用來判斷「信心越高是否越準」。
  - 每筆分析都看得到自己的回測結果與漲跌幅，方便追查。
- **Out of Scope:**
  - 追蹤標的的時段評等、綜合評等的回測。
  - 美股的價格（美股一律無法評估）。
  - 自動到價格服務登錄代號或補齊歷史價格。
  - 把回測結果存起來，或每天定時計算。
  - 依時間範圍以外的天數（例如固定 1、5、20 天）檢查。

---

## 2. User Personas

- **Primary Role(s):** 持有已啟用 API key 的使用者（實際上是專案擁有者本人）。
- **Usage Context:** 不定期查詢，用來檢視 AI 評等的品質，決定是否要調整分析方式。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 依評等方向判斷單筆分析是否命中 [priority: P0]
**As a** 使用者, **I want** 每筆分析都依時間範圍到期時的價格判斷評等方向對不對, **so that** 我知道 AI 的判斷有沒有用。

```gherkin
Scenario: 看多且之後上漲為命中
  Given 一筆看多、時間範圍短期的分析，起點價格 100
  And 分析後第 10 個交易日收盤價 105
  When 使用者查詢評等回測
  Then 該筆回測結果為「命中」，漲跌幅 +5%

Scenario: 看空且之後下跌為命中
  Given 一筆看空、時間範圍中期的分析，起點價格 100
  And 分析後第 60 個交易日收盤價 92
  When 使用者查詢評等回測
  Then 該筆回測結果為「命中」，漲跌幅 −8%

Scenario: 強烈看多但之後下跌為沒命中
  Given 一筆強烈看多、時間範圍短期的分析，起點價格 100
  And 分析後第 10 個交易日收盤價 97
  When 使用者查詢評等回測
  Then 該筆回測結果為「沒命中」，漲跌幅 −3%

Scenario: 看多但價格沒變為沒命中
  Given 一筆看多的分析，起點價格 100
  And 檢查點收盤價 100
  When 使用者查詢評等回測
  Then 該筆回測結果為「沒命中」，漲跌幅 0%

Scenario: 中性評等不計入命中率
  Given 一筆中性的分析，起點價格 100
  And 檢查點收盤價 103
  When 使用者查詢評等回測
  Then 該筆回測結果為「中性」，漲跌幅 +3%
  And 該筆不計入命中率，只計入中性評等的平均漲跌幅
```

### US-02 — 起點價格取分析完成那一分鐘 [priority: P0]
**As a** 使用者, **I want** 回測從分析完成那一刻的價格算起, **so that** 結果反映「看到評等當下照做」會怎樣。

```gherkin
Scenario: 交易時段內完成的台股分析
  Given 2330（台股）的分析在週三 10:15 完成
  And 價格服務中週三 10:15 那一分鐘的價格為 1000
  When 使用者查詢評等回測
  Then 該筆的起點價格為 1000

Scenario: 收盤後完成的台股分析
  Given 2330（台股）的分析在週三 20:30 完成
  And 價格服務中週三收盤前最後一筆價格為 1010
  When 使用者查詢評等回測
  Then 該筆的起點價格為 1010

Scenario: 週末完成的加密貨幣分析
  Given BTC（加密貨幣）的分析在週六 03:00 完成
  And 價格服務中週六 03:00 那一分鐘的價格為 86000
  When 使用者查詢評等回測
  Then 該筆的起點價格為 86000

Scenario: 開盤前完成的台股分析，完成當天即為第 1 個交易日
  Given 2330（台股）的分析在週四 07:30 完成
  And 價格服務中週三收盤前最後一筆價格為 1010
  When 使用者查詢評等回測
  Then 該筆的起點價格為 1010
  And 週四是分析後第 1 個交易日

Scenario: 交易時段內完成的台股分析，完成當天不算交易日
  Given 2330（台股）的分析在週三 10:15 完成
  When 使用者查詢評等回測
  Then 週四是分析後第 1 個交易日

Scenario: 分析時價格未取得仍可評估
  Given 一筆分析的分析時價格為「未取得」
  And 價格服務有該標的分析完成那一分鐘與檢查點的價格
  When 使用者查詢評等回測
  Then 該筆的回測結果為「命中」或「沒命中」，不是「無法評估」
```

### US-03 — 無法判斷的分析列出但不計入命中率 [priority: P0]
**As a** 使用者, **I want** 還沒到期或查不到價格的分析被清楚標示, **so that** 命中率不會被這些分析扭曲，我也知道有多少筆沒算進去。

```gherkin
Scenario: 檢查點那天還在交易
  Given 一筆時間範圍短期的分析，分析後第 10 個交易日就是今天
  And 今天還沒收盤
  When 使用者查詢評等回測
  Then 該筆回測結果為「尚未到期」，不用今天盤中的價格判斷

Scenario: 沒有每日價格的日子不算交易日
  Given 一筆時間範圍短期的分析，分析後的日子中有一天是國定假日，價格服務沒有那天的每日價格
  When 使用者查詢評等回測
  Then 檢查點往後延一天，國定假日不算進 10 個交易日

Scenario: 時間範圍尚未走完
  Given 一筆時間範圍短期的分析，分析後才過了 7 個交易日
  When 使用者查詢評等回測
  Then 該筆回測結果為「尚未到期」
  And 不計入命中率，計入「尚未到期」筆數

Scenario: 美股無法評估
  Given 一筆 AAPL（美股）的分析
  When 使用者查詢評等回測
  Then 該筆回測結果為「無法評估」
  And 不計入命中率，計入「無法評估」筆數

Scenario: 起點價格不是正數
  Given 一筆分析，價格服務給的起點價格為 0
  When 使用者查詢評等回測
  Then 該筆回測結果為「無法評估」

Scenario: 一筆無法評估不影響其他分析
  Given 6488（台股）在價格服務沒有價格，2330（台股）看多且之後上漲
  When 使用者查詢評等回測
  Then 6488 為「無法評估」，2330 為「命中」

Scenario: 價格服務沒有登錄的代號無法評估
  Given 一筆 6488（台股）的分析
  And 價格服務沒有登錄 6488
  When 使用者查詢評等回測
  Then 該筆回測結果為「無法評估」

Scenario: 失敗的分析不出現
  Given 一筆失敗的分析事件
  When 使用者查詢評等回測
  Then 回測的逐筆明細中沒有這筆分析，各項筆數也不包含它
```

**As a** 使用者, **I want** 一次看到整體與分組的命中率，並附上每筆明細, **so that** 我能判斷評等是否優於隨機，並追查個別結果。

## 4. Business Flow & Logic

- **Flow:**
  1. 使用者以已啟用的 API key 查詢評等回測（可指定分析完成期間、可指定標的 + 市場類別）。
  2. 找出符合條件的已完成使用者分析；超過 500 筆即拒絕。
  3. 每筆分析：價格服務查不到該標的 → 無法評估；檢查點尚未到 → 尚未到期；否則取起點價格與檢查點收盤價，依評等判斷結果。
  4. 彙總成整體、依市場類別 / 評等 / 信心分組的命中率，附中性平均漲跌幅、各結果筆數與逐筆明細。
- **Core Business Rules:**
  - 起點價格：分析完成那一分鐘的價格；該市場當下不在交易中，用分析完成前最後一筆價格。
  - 檢查點：短期為分析後第 10 個交易日、中期為第 60 個交易日的收盤價。「分析後第 1 個交易日」是起點價格所屬那一天之後的第一個交易日：交易時段內或收盤後完成的分析，完成當天不算；台股開盤前完成的分析，起點價格是前一個交易日的收盤，所以完成當天就是第 1 個交易日。
  - 交易日：價格服務有當天每日價格的日子；加密貨幣每天都是交易日。
  - 漲跌幅 = (檢查點收盤價 − 起點價格) ÷ 起點價格。
  - 看多 / 強烈看多：漲跌幅 > 0 為命中，其餘沒命中。看空 / 強烈看空：漲跌幅 < 0 為命中，其餘沒命中。中性：不判斷命中。
  - 命中率 = 命中 ÷（命中 + 沒命中）；分母為 0 時為「沒有資料」。
  - 信心分組：0–49 低、50–74 中、75–100 高。
  - 價格一律以精確小數計算，不可有浮點誤差。
  - 漲跌幅、中性平均漲跌幅與命中率四捨五入到小數 4 位。
  - 某一天還在交易（尚未收盤）時，那一天不算已走完的交易日。台股以台北時間 13:30 收盤為準；加密貨幣全天交易，以世界標準時間當日結束為準。
  - 只回測狀態為「已完成」的分析事件；即使留有分析結果，失敗或分析中的事件也不列入。
- **Edge Cases:**
  - 價格服務對單一標的查不到 → 該筆無法評估，其餘照算。
  - 價格服務整個無法連線 → 整次查詢失敗。
  - 期間內沒有任何分析 → 回傳空的總表，命中率皆為「沒有資料」。

## 6. Non-Functional Requirements

- **Performance:** 一次查詢最多涵蓋 500 筆分析；查詢時當場計算，不保存結果。
- **Security:** 受保護功能，需要已啟用且未撤銷的 API key。價格服務的登入憑證不得出現在任何回應中。

## 7. Dependencies & Risks

- **External Dependencies:** 價格服務（自家交易服務），提供台股與加密貨幣每分鐘、每日價格；需以專案擁有者帳號登入。
- **Known Risks:**
  - 價格服務的登入會定期過期並需要換發，登入失效時所有回測查詢都會失敗；登入如何保存與更新於技術設計階段決定。
  - 價格服務只有已登錄代號的價格，未登錄的標的會被標為無法評估，可能讓可評估樣本偏少。
  - 價格服務可回溯的每分鐘價格若不夠久，舊分析的起點價格可能取不到而成為無法評估。
  - 樣本少時命中率不具參考性；總表一律附上筆數供判斷。
