# 追蹤標的時段評等 — Requirements Brief

## Goal
目前只有使用者主動呼叫時才會分析標的。本功能讓系統維護一份「追蹤標的」清單，並在台股每個交易日的三個時段（盤前、盤中、盤後）自動分析清單上的台股標的：每個時段只看該時段的新聞，產出一筆「時段評等」，再把當天已有的時段評等依時段權重加權平均成一筆「綜合評等」。結果只保留當天：下一個交易日盤前開始時，前一天的時段評等與綜合評等一律刪除。使用者以已啟用的 API key 查詢追蹤標的的綜合評等與各時段評等。既有的「發起分析」流程與其分析事件、分析結果完全不受影響。

## Requirements
- **追蹤標的清單**
  - 每個追蹤標的由「標的 + 市場類別」組成，市場類別沿用既有的加密貨幣、台股、美股三種。
  - 同一個標的 + 市場類別在清單上只能出現一次。
  - 每個追蹤標的有「追蹤中 / 暫停」的開關；暫停的標的不自動分析。
  - 清單由 administrator 直接維護（比照啟用 API key 的做法），不提供管理功能。
  - 自動分析目前只處理市場類別為台股的追蹤標的；其他市場類別可以登記，但暫不分析。
- **交易時段與排程**（一律以台北時間計）
  - 只在週一到週五執行；週六、週日不執行。國定假日不另外判斷。
  - 每個交易日三個時段，各在自己的執行時段內自動執行一次：
    - 盤前：08:00–09:00 執行；看「前一個交易日 13:30 之後」到現在發布的新聞。
    - 盤中：12:30–13:30 執行；看「當天 09:00 之後」到現在發布的新聞。
    - 盤後：20:00–23:59 執行；看「當天 13:30 之後」到現在發布的新聞。
  - 「前一個交易日」= 前一個週一到週五的日子（週一的前一個交易日是上週五）。
  - 同一個交易日的同一個時段只執行一次，不論成功或失敗；服務在整個執行時段都沒在運作，該時段就跳過。
  - 自動分析不適用「6 小時內重用既有分析」的規則，每個時段都重新分析。
  - 一次只分析一個標的，依序進行。單一標的分析失敗不影響其他標的。
- **時段評等**
  - 每個追蹤標的每個交易日每個時段最多一筆時段評等，內容包含：評等、信心指數、分析理由、關鍵事件、風險因子。
  - 時段評等的評等、信心指數等，與既有分析結論相同的正規化規則（非法評等→中性、信心指數限制在 0–100）。
  - 該時段完全沒有新聞時，時段評等為中性、信心指數 0（比照既有規則）。
  - 時段評等不記錄分析時價格。
- **綜合評等**
  - 每個追蹤標的每個交易日一筆綜合評等；每當有新的時段評等產生，就用當天「已有的」時段評等重新計算並覆蓋。
  - 評等換成分數：強烈看多 +2、看多 +1、中性 0、看空 −1、強烈看空 −2。
  - 綜合分數 = 各已有時段的分數 × 時段權重，加總後除以這些時段的權重總和（加權平均，不是相乘）。
  - 綜合信心指數 = 各已有時段的信心指數，用同樣的權重做加權平均，四捨五入成整數。
  - 綜合分數換回評等：≥ 1.5 強烈看多；≥ 0.5 看多；> −0.5 中性；> −1.5 看空；其餘強烈看空。
  - 時段權重預設：盤後 0.5、盤前 0.3、盤中 0.2，可由設定調整；設定值不是正數時使用預設值。
- **只保留一天**
  - 每次盤前開始時，先刪除所有「不是今天交易日」的時段評等與綜合評等，再開始分析。
  - 盤後執行完之後到隔天盤前開始之前，前一天的資料仍可查詢（例如週六可以查到週五的結果）。
- **查詢**
  - 使用者以已啟用的 API key 查詢追蹤標的的評等：回傳每個有綜合評等的追蹤標的，其交易日、綜合評等、綜合信心指數，以及當天各時段的時段評等。
  - 可以只查某一個標的 + 市場類別；該標的沒有評等時回傳空的結果，不是錯誤。
- **執行紀錄**
  - 每一次時段執行（某交易日的某時段）留下一筆執行紀錄：交易日、時段、狀態（執行中 / 已完成 / 失敗）、開始與結束時間、成功與失敗的標的數。
  - 服務重新啟動時，仍為「執行中」的執行紀錄改為失敗，原因「服務重新啟動，執行中斷」。
  - 執行紀錄不受「只保留一天」限制。
- **專案文件**
  - 專案成功指標「評等可回測驗證」改寫為：只適用於使用者發起的分析（保留歷史）；自動時段評等只保留當天，不做回測。

## Examples (Specification by Example)

### Rule: 只分析追蹤中的台股標的
| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 清單有 2330 / 台股，追蹤中 | 盤前執行 | 2330 產生一筆盤前時段評等 |
| 2 (exception) | 清單有 2317 / 台股，暫停 | 盤前執行 | 2317 不分析 |
| 3 (exception) | 清單有 AAPL / 美股，追蹤中 | 盤前執行 | AAPL 不分析 |
| 4 (boundary) | 清單沒有任何追蹤中的台股標的 | 盤前執行 | 不分析任何標的，執行紀錄為已完成、成功 0 檔 |

### Rule: 時段的執行時間與新聞範圍
| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 週三 08:00 | 系統檢查 | 執行週三盤前，新聞範圍：週二 13:30 之後 |
| 2 (boundary) | 週一 08:30 | 系統檢查 | 執行週一盤前，新聞範圍：上週五 13:30 之後 |
| 3 (happy) | 週三 12:30 | 系統檢查 | 執行週三盤中，新聞範圍：週三 09:00 之後 |
| 4 (happy) | 週三 20:00 | 系統檢查 | 執行週三盤後，新聞範圍：週三 13:30 之後 |
| 5 (boundary) | 週三 09:00 整 | 系統檢查 | 不在任何執行時段，不執行 |
| 6 (boundary) | 週三 23:59 | 系統檢查，盤後尚未執行 | 執行週三盤後 |
| 7 (exception) | 週六 08:30 | 系統檢查 | 不執行 |
| 8 (exception) | 週三盤前已執行過（成功或失敗） | 週三 08:40 系統再次檢查 | 不再執行 |
| 9 (exception) | 服務在週三 12:00–14:00 停機 | 服務 14:00 恢復 | 週三盤中跳過，不補跑 |

### Rule: 新聞只看該時段範圍
| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 週三盤中；新聞 A 週三 10:15 發布、新聞 B 週二 21:00 發布 | 盤中分析 2330 | 只用新聞 A |
| 2 (boundary) | 週三盤中；新聞發布於週三 09:00 整 | 盤中分析 2330 | 這則新聞算在盤中範圍內 |
| 3 (exception) | 週三盤中；範圍內沒有任何新聞 | 盤中分析 2330 | 盤中時段評等為中性、信心指數 0 |

### Rule: 自動分析不重用既有分析
| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 2330 一小時前已有使用者發起的分析 | 盤中執行 | 仍重新分析 2330，產生盤中時段評等；使用者的分析不受影響 |

### Rule: 綜合評等是已有時段的加權平均
權重：盤後 0.5、盤前 0.3、盤中 0.2。
| # | Given（當天已有的時段評等） | When | Then |
|---|---|---|---|
| 1 (happy) | 盤前 看多（+1）、信心 60 | 盤前完成 | 綜合分數 +1 → 看多；綜合信心 60 |
| 2 (happy) | 盤前 看多（+1）/ 信心 60；盤中 看空（−1）/ 信心 40 | 盤中完成 | (0.3×1 + 0.2×−1) / 0.5 = +0.2 → 中性；信心 (0.3×60 + 0.2×40) / 0.5 = 52 |
| 3 (happy) | 盤前 強烈看多（+2）；盤中 看多（+1）；盤後 看空（−1） | 盤後完成 | (0.6 + 0.2 − 0.5) / 1.0 = +0.3 → 中性 |
| 4 (boundary) | 盤前 看多（+1）；盤後 看多（+1）；盤中失敗沒有評等 | 盤後完成 | 只用盤前與盤後：(0.3 + 0.5) / 0.8 = +1 → 看多 |
| 5 (boundary) | 綜合分數剛好 +0.5 | 重算 | 看多 |
| 6 (boundary) | 綜合分數剛好 −0.5 | 重算 | 看空 |
| 7 (boundary) | 綜合分數剛好 +1.5 | 重算 | 強烈看多 |
| 8 (boundary) | 綜合分數剛好 −1.5 | 重算 | 強烈看空 |
| 9 (exception) | 盤後權重被設成 0 | 服務啟動 | 盤後權重使用預設 0.5 |

### Rule: 同時段重新產生時覆蓋，不疊加
| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 2330 當天已有盤前與盤中評等，綜合為中性 | 盤後完成 | 綜合評等改為三段重算的結果，仍只有一筆 |

### Rule: 只保留一天
| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 有週二的時段評等與綜合評等 | 週三盤前開始 | 週二資料全部刪除，再寫入週三盤前結果 |
| 2 (boundary) | 週五盤後已完成 | 週六查詢 | 仍查得到週五的結果 |
| 3 (boundary) | 有週五的資料 | 週一盤前開始 | 週五資料刪除 |
| 4 (exception) | 週三盤前整段停機沒執行；有週二資料 | 週三 12:30 盤中開始 | 週二資料仍保留（只有盤前會刪除），盤中寫入週三的時段評等與綜合評等 |

### Rule: 單一標的失敗不影響其他標的
| # | Given | When | Then |
|---|---|---|---|
| 1 (exception) | 追蹤 2330、2317；分析 2330 時 AI 服務無法使用 | 盤前執行 | 2330 沒有盤前評等；2317 照常產生；執行紀錄已完成，成功 1、失敗 1 |
| 2 (exception) | 盤前執行中服務重新啟動 | 服務啟動 | 該筆執行紀錄改為失敗，原因「服務重新啟動，執行中斷」；當天盤前不再重跑 |

### Rule: 查詢追蹤標的評等
| # | Given | When | Then |
|---|---|---|---|
| 1 (happy) | 2330 有週三盤前、盤中評等與綜合評等；API key 已啟用 | 查詢 | 回傳 2330：交易日週三、綜合評等、綜合信心、盤前與盤中的時段評等 |
| 2 (boundary) | 指定 2603 / 台股，沒有評等 | 查詢 | 回傳空的結果 |
| 3 (exception) | API key 停用中 | 查詢 | 拒絕，告知尚未啟用（比照既有受保護功能） |
| 4 (exception) | 指定的市場類別不是三種之一 | 查詢 | 拒絕，告知市場類別只能是三種之一 |

## Out of Scope
- 美股與加密貨幣的自動分析。
- 台股國定假日 / 颱風假判斷。
- 錯過的時段補跑；失敗標的在同時段內重試。
- 管理追蹤標的清單的功能（由 administrator 直接維護）。
- 時段評等的分析時價格與回測。
- 時段評等的歷史保存。

## Open Decisions
- 時段新聞範圍如何套用到既有的新聞搜尋（新聞搜尋本身保留 7 天內新聞，時段範圍更窄）。
- 系統多久檢查一次是否進入執行時段。
- 時段評等是否沿用既有分析的 AI 用量紀錄方式。

## Context / Background
- 使用者決定：結果只保留一天、直接刪除；以加權平均取代相乘；三段各存一筆再算綜合，不疊加；照時段挑新聞、不照分數挑。
- 盤中新聞多半當天就反映在股價上，對下一個交易日影響最小，所以權重最低；收盤後到開盤前的新聞影響下一個交易日開盤，權重較高。
- 盤前的新聞範圍從前一個交易日收盤起算，前一天盤後的新聞因此會被帶進今天；前一天盤中的新聞則自然不再採用。
- 既有分析的「6 小時內重用」與「同時最多 4 個分析」只適用使用者發起的分析。
