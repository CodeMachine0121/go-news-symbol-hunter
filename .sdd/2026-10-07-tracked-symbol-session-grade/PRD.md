# Product Requirements Document (PRD) — 追蹤標的時段評等

**Status:** Finalized
**Version:** v1.1
**Owner:** James Hsueh
**Stakeholders:** Engineering

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:** 目前只有使用者主動發起時才會分析標的。想每天掌握固定幾檔台股的資訊面，就得自己一檔一檔、一天好幾次地發起分析，而且分析看的是 7 天內全部新聞，分不出「今天盤前、盤中、盤後」各發生了什麼、對下一個交易日的影響有多大。
- **Expected Outcome:**
  - administrator 登記追蹤標的後，台股追蹤標的每個交易日自動產出盤前、盤中、盤後三筆時段評等。
  - 每個追蹤標的每個交易日有一筆綜合評等，是當天已有時段評等的加權平均，隨時段推進即時更新。
  - 使用者以已啟用的 API key 一次查到所有追蹤標的的綜合評等與各時段評等。
  - 時段評等與綜合評等只保留當天，不累積歷史。
- **Out of Scope:**
  - 美股與加密貨幣的自動分析（可登記，暫不分析）。
  - 台股國定假日、颱風假判斷。
  - 錯過的時段補跑；失敗標的在同時段內重試。
  - 管理追蹤標的清單的功能（administrator 直接維護）。
  - 時段評等的分析時價格、回測與歷史保存。
  - 改變使用者發起分析的任何行為。

---

## 2. User Personas

- **Primary Role(s):**
  - Administrator：維護追蹤標的清單、調整時段權重。
  - 持有已啟用 API key 的使用者：查詢追蹤標的評等。
- **Usage Context:** 系統於台股交易日依台北時間自動執行；使用者以程式在任何時間查詢，通常在開盤前或收盤後查看。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 只自動分析追蹤中的台股標的 [priority: P0]
**As a** administrator, **I want** 系統只分析我登記且追蹤中的台股標的, **so that** AI 費用只花在我在意的標的上。

```gherkin
Scenario: 追蹤中的台股標的產生時段評等
  Given 追蹤標的清單有 2330（台股），追蹤中
  When 盤前時段執行
  Then 2330 產生一筆當天的盤前時段評等

Scenario: 暫停的標的不分析
  Given 追蹤標的清單有 2317（台股），暫停
  When 盤前時段執行
  Then 2317 沒有任何時段評等

Scenario: 非台股的追蹤標的不分析
  Given 追蹤標的清單有 AAPL（美股），追蹤中
  When 盤前時段執行
  Then AAPL 沒有任何時段評等

Scenario: 沒有可分析的標的仍完成執行
  Given 追蹤標的清單沒有任何追蹤中的台股標的
  When 盤前時段執行
  Then 該次時段執行紀錄為「已完成」，成功 0 檔、失敗 0 檔

Scenario: 同一標的同一市場類別只能登記一次
  Given 追蹤標的清單已有 2330（台股）
  When administrator 再登記一次 2330（台股）
  Then 登記不成立，清單上 2330（台股）仍只有一筆
```

### US-02 — 依交易時段自動執行 [priority: P0]
**As a** administrator, **I want** 系統在每個交易日的盤前、盤中、盤後各自動執行一次, **so that** 我不必手動觸發。

```gherkin
Scenario: 週三盤前執行
  Given 現在是週三 08:00（台北時間）
  And 週三盤前尚未執行
  When 系統檢查是否該執行
  Then 執行週三的盤前時段，新聞範圍為「週二 13:30 之後」

Scenario: 週一盤前的新聞範圍從上週五收盤起算
  Given 現在是週一 08:30
  When 系統檢查是否該執行
  Then 執行週一的盤前時段，新聞範圍為「上週五 13:30 之後」

Scenario: 週三盤中執行
  Given 現在是週三 12:30
  When 系統檢查是否該執行
  Then 執行週三的盤中時段，新聞範圍為「週三 09:00 之後」

Scenario: 週三盤後執行
  Given 現在是週三 20:00
  When 系統檢查是否該執行
  Then 執行週三的盤後時段，新聞範圍為「週三 13:30 之後」

Scenario: 執行時段結束的那一刻不執行
  Given 現在是週三 09:00 整
  When 系統檢查是否該執行
  Then 不執行任何時段

Scenario: 盤後執行時段的最後一分鐘仍執行
  Given 現在是週三 23:59
  And 週三盤後尚未執行
  When 系統檢查是否該執行
  Then 執行週三的盤後時段

Scenario: 週末不執行
  Given 現在是週六 08:30
  When 系統檢查是否該執行
  Then 不執行任何時段

Scenario: 同時段只執行一次
  Given 週三盤前已執行過（不論成功或失敗）
  When 週三 08:40 系統再次檢查
  Then 不再執行週三盤前

Scenario: 錯過的時段不補跑
  Given 服務在週三 12:00 到 14:00 停機
  When 服務在週三 14:00 恢復
  Then 週三盤中沒有執行紀錄，也沒有盤中時段評等
```

### US-03 — 時段評等只看該時段的新聞 [priority: P0]
**As a** 使用者, **I want** 每個時段評等只根據該時段的新聞, **so that** 我看得出每個時段各自的資訊面。

```gherkin
Scenario: 範圍外的新聞不採用
  Given 週三盤中執行
  And 新聞 A 於週三 10:15 發布，新聞 B 於週二 21:00 發布
  When 分析 2330
  Then 盤中時段評等的佐證只有新聞 A

Scenario: 剛好在範圍起點發布的新聞採用
  Given 週三盤中執行
  And 一則新聞於週三 09:00 整發布
  When 分析 2330
  Then 這則新聞列入盤中時段評等的佐證

Scenario: 範圍內沒有新聞時為中性
  Given 週三盤中執行
  And 範圍內沒有任何 2330 的新聞
  When 分析 2330
  Then 盤中時段評等為「中性」，信心指數 0

Scenario: 自動分析不重用使用者發起的分析
  Given 2330 一小時前已有使用者發起的已完成分析
  When 週三盤中執行
  Then 2330 重新分析並產生盤中時段評等
  And 使用者發起的那次分析事件與分析結果不變
```

### US-04 — 綜合評等是已有時段評等的加權平均 [priority: P0]
**As a** 使用者, **I want** 一個把當天各時段合起來的綜合評等, **so that** 我一眼就知道今天整體偏多還是偏空。

時段權重：盤後 0.5、盤前 0.3、盤中 0.2。評等分數：強烈看多 +2、看多 +1、中性 0、看空 −1、強烈看空 −2。

```gherkin
Scenario: 只有盤前時綜合等於盤前
  Given 2330 當天只有盤前時段評等「看多」，信心指數 60
  When 綜合評等重新計算
  Then 綜合評等為「看多」，綜合信心指數 60

Scenario: 盤前與盤中加權平均
  Given 2330 當天盤前「看多」信心 60，盤中「看空」信心 40
  When 綜合評等重新計算
  Then 綜合分數為 +0.2，綜合評等為「中性」
  And 綜合信心指數為 52

Scenario: 三個時段加權平均
  Given 2330 當天盤前「強烈看多」，盤中「看多」，盤後「看空」
  When 綜合評等重新計算
  Then 綜合分數為 +0.3，綜合評等為「中性」

Scenario: 缺少的時段不列入計算
  Given 2330 當天盤前「看多」，盤後「看多」，盤中沒有時段評等
  When 綜合評等重新計算
  Then 綜合分數為 +1，綜合評等為「看多」

Scenario Outline: 綜合分數換回評等的邊界
  Given 2330 的綜合分數為 <分數>
  When 綜合評等重新計算
  Then 綜合評等為「<評等>」

  Examples:
    | 分數 | 評等     |
    | +1.5 | 強烈看多 |
    | +0.5 | 看多     |
    | +0.4 | 中性     |
    | -0.4 | 中性     |
    | -0.5 | 看空     |
    | -1.5 | 強烈看空 |

Scenario: 權重設定不是正數時使用預設值
  Given 盤後權重設定為 0
  When 服務啟動
  Then 盤後權重為 0.5

Scenario: 新時段完成時覆蓋當天的綜合評等
  Given 2330 當天已有盤前與盤中時段評等，綜合評等為「中性」
  When 盤後時段評等產生
  Then 2330 當天仍只有一筆綜合評等，內容為三個時段重新計算的結果
```

### US-05 — 只保留當天的結果 [priority: P0]
**As a** administrator, **I want** 時段評等與綜合評等只保留當天, **so that** 資料不會累積，查到的永遠是最新一天。

```gherkin
Scenario: 盤前開始時刪除前一天的結果

  When 週三盤前開始執行
  Then 週二的時段評等與綜合評等全部刪除
  And 之後寫入週三的盤前時段評等與綜合評等

Scenario: 週末仍查得到週五的結果
  Given 週五盤後已完成
  When 使用者在週六查詢
  Then 查得到週五的綜合評等與時段評等

Scenario: 週一盤前刪除週五的結果
  Given 有週五的時段評等與綜合評等
  When 週一盤前開始執行
  Then 週五的時段評等與綜合評等全部刪除

Scenario: 只有盤前會刪除前一天的結果
  Given 有週二的時段評等與綜合評等
  And 週三盤前因停機沒有執行
  When 週三盤中執行
  Then 週二的結果仍保留
  And 新增週三的盤中時段評等與綜合評等

Scenario: 同一標的有兩天的結果時只查得到最新一天
  Given 2330 有週二與週三的綜合評等
  When 使用者查詢追蹤標的評等
  Then 2330 只出現一次，交易日為週三
```

### US-06 — 單一標的失敗不影響其他標的 [priority: P0]
**As a** administrator, **I want** 一檔標的分析失敗時其他標的照常完成, **so that** 一次故障不會讓整個時段落空。

```gherkin
Scenario: 一檔失敗其他照常
  Given 追蹤 2330 與 2317（台股，追蹤中）
  And 分析 2330 時 AI 服務暫時無法使用
  When 盤前時段執行
  Then 2330 沒有盤前時段評等
  And 2317 產生盤前時段評等
  And 該次時段執行紀錄為「已完成」，成功 1 檔、失敗 1 檔

Scenario: 服務重新啟動中斷執行
  Given 週三盤前時段執行中
  When 服務重新啟動
  Then 該次時段執行紀錄改為「失敗」，原因「服務重新啟動，執行中斷」
  And 週三盤前不再重新執行
```

## 4. Business Flow & Logic

- **Flow:**
  1. 系統定期檢查台北時間：若為週一到週五，且落在某個時段的執行時段內，且該交易日該時段沒有執行紀錄 → 建立執行紀錄（執行中）。
  2. 若為盤前：先刪除所有不是今天交易日的時段評等與綜合評等。
  3. 取得所有追蹤中、市場類別為台股的追蹤標的，依序逐檔：以該時段的新聞範圍讓 AI 分析 → 正規化結論 → 保存時段評等（同標的同交易日同時段若已存在則覆蓋）→ 以當天所有時段評等重新計算並保存綜合評等。
  4. 全部標的處理完 → 執行紀錄改為已完成，記下成功與失敗檔數。
- **Core Business Rules:**
  - 時段與執行時段（台北時間）：盤前 08:00 起、09:00 前；盤中 12:30 起、13:30 前；盤後 20:00 起、24:00 前。起點含、終點不含。
  - 新聞範圍（起點含、終點不含）：盤前 = 前一個交易日 13:30 起、當天 09:00 前；盤中 = 當天 09:00 起、13:30 前；盤後 = 當天 13:30 起、24:00 前。終點為該時段收盤，執行跨出執行時段時也不會讀到下一個時段的新聞。另受既有新聞搜尋「7 天內、最多 30 則」的限制。
  - 前一個交易日 = 往前最近的週一到週五。
  - 交易日 = 執行當天的日期（台北時間）。
  - 時段評等的正規化規則與使用者發起分析的分析結論相同（非法評等→中性、信心指數 0–100、關鍵事件只採用實際讀過的新聞、最多 5 則；風險因子最多 5 則）；範圍內沒有新聞 → 中性、信心指數 0。
  - 綜合分數 = Σ(時段分數 × 時段權重) ÷ Σ(已有時段的權重)；綜合信心指數 = Σ(信心指數 × 權重) ÷ Σ(權重)，四捨五入成整數。
  - 綜合分數換回評等：≥ 1.5 強烈看多；≥ 0.5 看多；> −0.5 中性；> −1.5 看空；其餘強烈看空。
  - 時段權重預設盤後 0.5、盤前 0.3、盤中 0.2，可由設定調整；不是正數時用預設值。
  - 一個標的的分析沿用使用者發起分析的單次上限（10 分鐘、最多 5 輪 AI 工具使用）。
  - 自動分析不建立分析事件、不寫入分析結果、不受「6 小時內重用」與「同時最多 4 個分析」限制。
  - 執行紀錄狀態：執行中 → 已完成 / 失敗。執行紀錄永久保留。
  - 執行紀錄另記錄每檔失敗標的與其失敗原因（標的辨識失敗、AI 失敗原因、「時段評等保存失敗」、「綜合評等保存失敗」），以及本次所有標的（含失敗者）的 AI 用量合計。
  - 查詢只列出目前仍追蹤中的標的（暫停或移除者不列出）；同一標的若存有兩個交易日的結果，只列最新一天。
  - 查詢結果除綜合評等、綜合信心指數外，另附綜合分數與最後更新時間；每筆時段評等另附佐證（AI 讀過的新聞）與產生時間，供稽核。
  - 自動分析可整體關閉（背景作業總開關），也可調整系統檢查時段的頻率（預設每 60 秒）；設為 0 即停用。
  - 總開關、檢查頻率、時段權重有設定但無法解讀（如 `0,5`、`maybe`）時，服務拒絕啟動；未設定則用預設值。
- **Edge Cases:**
  - 單一標的 AI 失敗、逾時、拒絕、新聞來源全部失敗 → 該標的計為失敗，不產生該時段評等，綜合評等不變；繼續下一檔。
  - 保存時段評等或綜合評等失敗 → 該標的計為失敗。
  - 建立執行紀錄失敗 → 本次不執行，等下一次檢查。
  - 刪除前一天的結果失敗 → 執行紀錄改為失敗（原因「前一天結果刪除失敗」），本時段不分析。
  - 讀取追蹤標的清單失敗 → 執行紀錄改為失敗（原因「追蹤標的讀取失敗」）。
  - 查詢時指定市場類別但標的為空白 → 查詢被拒，告知「標的為必填」。
  - 服務在執行中重新啟動 → 啟動時將執行中的執行紀錄改為失敗（「服務重新啟動，執行中斷」）。
  - 追蹤標的在清單上但台股查無此標的 → 該標的計為失敗。

## 6. Non-Functional Requirements

- **Performance:** 依序分析，每檔最多 10 分鐘；追蹤標的數量多時，一個時段可能跨出執行時段才完成，屬可接受（新聞範圍終點固定在時段收盤，評等不受影響）。依序是為了 AI 成本可預期，且不與使用者發起的分析搶 AI 用量。
- **Security:** 查詢需已啟用且未撤銷的 API key（受保護功能）。追蹤標的清單與權重只能由 administrator 透過資料與設定維護。
- **Compatibility:** 時間一律以台北時間判斷。
- **Analytics / Tracking:** 每次時段執行留下執行紀錄（成功 / 失敗檔數）；AI 用量記在時段評等上。

---

## 7. Dependencies & Risks

- **External Dependencies:** 既有的 AI 分析服務、台股新聞來源（鉅亨網、Google 新聞）、證交所 / 櫃買中心標的資料。
- **Known Risks:**
  - 新聞來源提供的發布時間不準時，時段歸屬可能偏差。
  - 國定假日仍會執行，產生的評等可能只有前一天延續的新聞，屬已知限制。
  - 追蹤標的多時 AI 成本為「標的數 × 3 次 / 交易日」。
