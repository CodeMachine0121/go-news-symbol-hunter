# Product Requirements Document (PRD) — 以名稱發起分析

**Status:** Finalized
**Version:** v1.0
**Owner:** James Hsueh
**Stakeholders:** Engineering, 使用者（操作台）

---

## 1. Background & Goal (Why & Goal)

- **Problem Statement:**
  - 使用者發起分析時，標的只能填代號，記不得代號就得先去別處查。
  - 台股上市 ETF（如 0050、00878）不在系統辨識用的上市名單內，被回覆「找不到此標的」。
  - 美股不做任何辨識，使用者填錯字（如「TESLA」）時，系統會把它當成代號去搜尋新聞、取分析時價格，分析的對象錯了卻沒有任何提示。
- **Expected Outcome:**
  - 三個市場類別都能以代號或名稱發起分析，且最終分析的一律是正確的代號。
  - 台股上市、上櫃的股票與 ETF 都能被辨識（0050、00878、00679B 都能分析）。
  - 名稱對到多個標的時，系統不猜，列出候選讓使用者選。
- **Out of Scope:**
  - 輸入時即時提示候選（自動完成）。
  - 名稱的中英對照（「特斯拉」→ TSLA、「比特幣」→ BTC）。
  - 權證、期貨、選擇權等衍生性商品。
  - 美股以外的海外市場。
  - 追蹤標的以名稱登記。
  - 搜尋標的新聞以名稱查詢。

---

## 2. User Personas

- **Primary Role(s):** 持有已啟用 API key 的使用者（透過操作台或直接呼叫）。
- **Usage Context:** 想分析某個標的、手邊只記得名稱時，直接在發起分析時填名稱。

---

## 3. User Stories & Acceptance Criteria

### US-01 — 台股以代號或名稱發起分析 [priority: P0]
**As a** 使用者，**I want** 台股可以填代號或公司簡稱（含 ETF 名稱）發起分析，**so that** 不必先查代號，ETF 也能分析。

```gherkin
Scenario: 以台股代號發起分析
  Given 2330 是上市股票「台積電」
  When 使用者以台股、填「2330」發起分析
  Then 系統分析 2330，標的名稱為「台積電」

Scenario: 以公司簡稱發起分析
  Given 2330 是上市股票「台積電」
  When 使用者以台股、填「台積電」發起分析
  Then 系統分析 2330，標的名稱為「台積電」

Scenario: 上市 ETF 可以被辨識
  Given 0050 是上市 ETF「元大台灣50」
  When 使用者以台股、填「0050」發起分析
  Then 系統分析 0050，標的名稱為「元大台灣50」

Scenario: 以上櫃 ETF 名稱發起分析
  Given 00679B 是上櫃 ETF「元大美債20年」
  When 使用者以台股、填「元大美債20年」發起分析
  Then 系統分析 00679B，標的名稱為「元大美債20年」

Scenario: 唯一部分符合即採用
  Given 名稱包含「台積」的台股只有「台積電」（2330）
  When 使用者以台股、填「台積」發起分析
  Then 系統分析 2330

Scenario: 完全相同優先於部分符合
  Given 「元大台灣50」（0050）與「元大台灣50正2」（00631L）的名稱都包含「元大台灣50」
  When 使用者以台股、填「元大台灣50」發起分析
  Then 系統分析 0050，不視為符合多個標的

Scenario: 名稱符合多個標的
  Given 名稱包含「國泰」的台股有十幾個，沒有名稱完全是「國泰」的
  When 使用者以台股、填「國泰」發起分析
  Then 不建立分析事件
  And 回覆「符合多個標的，請改填代號或更完整的名稱」，並列出最多 10 個候選，每個候選有代號與名稱

Scenario: 找不到標的
  Given 沒有任何台股的代號或名稱符合「台基電」
  When 使用者以台股、填「台基電」發起分析
  Then 回覆「找不到此標的」，不建立分析事件

Scenario: 權證不辨識
  Given 710001 是上櫃權證
  When 使用者以台股、填「710001」發起分析
  Then 回覆「找不到此標的」，不建立分析事件

Scenario: 台股名單暫時取不到
  Given 上市名單暫時取不到
  When 使用者以台股、填「台積電」發起分析
  Then 回覆新聞來源暫時無法使用，不回覆「找不到此標的」
```

### US-02 — 加密貨幣以代號或名稱發起分析 [priority: P0]
**As a** 使用者，**I want** 加密貨幣可以填代號或幣種名稱，**so that** 填「Bitcoin」也能分析 BTC。

```gherkin
Scenario: 以加密貨幣代號發起分析
  Given BTC 是「Bitcoin」，市值排名第 1
  When 使用者以加密貨幣、填「BTC」發起分析
  Then 系統分析 BTC，標的名稱為「Bitcoin」

Scenario: 以幣種名稱發起分析，不分大小寫
  Given BTC 是「Bitcoin」，市值排名第 1
  When 使用者以加密貨幣、填「bitcoin」發起分析
  Then 系統分析 BTC，標的名稱為「Bitcoin」

Scenario: 代號或名稱完全相同的有多個時取市值排名最前
  Given BTC 是「Bitcoin」，市值排名第 1
  And 另有一個幣種代號剛好是「BITCOIN」，市值排名在 Bitcoin 之後
  When 使用者以加密貨幣、填「Bitcoin」發起分析
  Then 系統分析 BTC

Scenario: 名稱符合多個幣種
  Given 名稱包含「Bitco」的幣種有 Bitcoin、Bitcoin Cash 等多個，沒有代號或名稱完全是「Bitco」的
  When 使用者以加密貨幣、填「Bitco」發起分析
  Then 不建立分析事件
  And 回覆「符合多個標的，請改填代號或更完整的名稱」，並列出候選，依市值排名由前到後

Scenario: 找不到幣種
  Given 沒有任何幣種的代號或名稱符合「ZZZQQ」
  When 使用者以加密貨幣、填「ZZZQQ」發起分析
  Then 回覆「找不到此標的」，不建立分析事件
```

### US-03 — 美股以代號或名稱發起分析 [priority: P0]
**As a** 使用者，**I want** 美股可以填代號或公司名稱，**so that** 填「Tesla」會分析 TSLA，而不是把錯字當代號。

```gherkin
Scenario: 以美股代號發起分析
  Given TSLA 是美國掛牌股票「Tesla, Inc.」
  When 使用者以美股、填「TSLA」發起分析
  Then 系統分析 TSLA，標的名稱為「Tesla, Inc.」

Scenario: 填的字不是已知標的時改以標的名稱比對
  Given TSLA 是美國掛牌股票「Tesla, Inc.」，沒有代號是 TESLA 的股票
  When 使用者以美股、填「TESLA」發起分析
  Then 系統分析 TSLA，不再以「TESLA」當代號

Scenario: 不計公司字尾後完全相同
  Given 「Apple Inc.」（AAPL）與「Apple Hospitality REIT, Inc.」（APLE）的名稱都包含 Apple
  When 使用者以美股、填「Apple」發起分析
  Then 系統分析 AAPL

Scenario: 名稱符合多個美股
  Given 名稱包含「SPDR S&P 500」的美國掛牌 ETF 有 SPY、SPYX、EFIV 等多個，沒有完全相同的
  When 使用者以美股、填「SPDR S&P 500」發起分析
  Then 不建立分析事件
  And 回覆「符合多個標的，請改填代號或更完整的名稱」，並列出候選

Scenario: 只考慮美國掛牌的股票與 ETF
  Given Tesla 在加拿大的掛牌 TSLA.TO 與 Tesla 期貨也出現在美股資料來源的結果中
  When 使用者以美股、填「Tesla」發起分析
  Then 系統分析 TSLA

Scenario: 美股資料來源可用但查無此標的
  Given 「ZZZZ」不是任何美股代號，也比對不到任何美股名稱
  And 美股資料來源正常
  When 使用者以美股、填「ZZZZ」發起分析
  Then 回覆「找不到此標的」，不建立分析事件

Scenario: 美股資料來源暫時無法使用
  Given 美股資料來源暫時無法使用
  When 使用者以美股、填「Tesla」發起分析
  Then 系統照現行把「TESLA」當代號分析，標的名稱為空
```

### US-04 — 填名稱與填代號視為同一個標的 [priority: P0]
**As a** 使用者，**I want** 填名稱和填代號被當成同一個標的，**so that** 重用時間窗內不會為同一家公司重複花 AI 費用。

```gherkin
Scenario: 名稱發起的分析重用代號發起的分析
  Given 2 小時前有一筆以「2330」發起、已完成的台股分析
  When 使用者以台股、填「台積電」發起分析
  Then 直接回傳那筆既有分析事件，不重新分析

Scenario: 超過重用時間窗時重新分析
  Given 7 小時前有一筆以「台積電」發起、已完成的台股分析，記為 2330
  When 使用者以台股、填「2330」發起分析
  Then 建立新的分析事件，標的為 2330
```

### US-05 — 追蹤標的自動分析不受影響 [priority: P1]
**As a** administrator，**I want** 追蹤標的照登記的代號自動分析，**so that** 既有排程不受本功能干擾，且 ETF 也能追蹤。

```gherkin
Scenario: 追蹤標的照常分析
  Given 追蹤標的 2330 / 台股
  When 盤前自動分析
  Then 以「台積電」搜尋新聞並產生時段評等

Scenario: 追蹤上市 ETF
  Given 追蹤標的 0050 / 台股
  When 盤前自動分析
  Then 以「元大台灣50」搜尋新聞並產生時段評等，不再因找不到標的而失敗
```

## 4. Business Flow & Logic

- **Flow:**
  1. 使用者帶標的（代號或名稱）與市場類別發起分析。
  2. 標的辨識：先當代號辨識；不是已知代號時，再當名稱比對。
  3. 辨識結果為「唯一標的」→ 以該代號照既有流程（重用或建立分析事件）。
  4. 辨識結果為「符合多個標的」→ 不建立分析事件，回覆候選。
  5. 辨識結果為「找不到」→ 回覆找不到此標的。
- **Core Business Rules:**
  - **名稱比對順序**：代號完全相同 → 名稱完全相同 → 名稱包含填的字。前一步有結果就不看下一步。
  - **比對正規化**：忽略前後空白、不分大小寫；美股名稱另外不計標點（逗號、句點）與結尾的公司字尾，公司字尾清單：Inc、Incorporated、Corp、Corporation、Co、Company、Ltd、Limited、PLC、LP、LLC、SA、NV、AG、Holdings。
  - **唯一性**：名稱完全相同的有多個時——台股依代號由小到大取第一個、加密貨幣取市值排名最前、美股取美股資料來源排序最前；名稱包含（部分符合）的有多個時則為符合多個標的。
  - **同代號只代表一個標的**：分析只以代號進行，代號一律代表排序最前的那一筆（如加密貨幣中市值排名最前者）；同代號但排序較後的商品不參與比對、也不列為候選。
  - **候選**：最多 10 個；台股依代號由小到大、加密貨幣依市值排名由前到後（沒有排名的排最後）、美股依美股資料來源回傳順序。
  - **台股辨識範圍**：上市（證交所每日收盤行情）與上櫃（櫃買中心每日收盤行情）所列的股票、ETF 與其他非權證商品；上櫃權證（代號 6 碼且以 7 開頭）不辨識。
  - **美股辨識範圍**：美國交易所（含 OTC 市場）掛牌、類型為股票或 ETF 者；美股資料來源沒有提供名稱的標的仍可以代號辨識，名稱為空。
  - **美股股票類別代號**：填的字是股票類別代號（如 BRK.B）時，以美股資料來源認得的寫法查詢，確保辨識到該股票本身，而不是名稱裡剛好提到它的其他商品。
  - **一律記成代號**：分析事件與分析結果的標的記為辨識出的代號；標的名稱依「標的名稱」規則（台股公司簡稱、加密貨幣幣種名稱、美股資料來源提供的公司名稱）。
  - **重用時間窗**：以辨識出的代號 + 市場類別判斷（與現行相同）。
- **Edge Cases:**
  - 台股或加密貨幣名單暫時取不到：回覆新聞來源暫時無法使用（現行行為），不判定找不到。
  - 美股資料來源暫時無法使用：以填的字（轉大寫）當代號照常分析、名稱為空（現行行為）。
  - 填的字是空白：回覆標的為必填（現行行為）。

## 6. Non-Functional Requirements

- **Performance:** 台股名單沿用既有的定時快取（每日收盤行情每小時更新一次），名稱比對不額外連線；美股名稱比對至多多一次美股資料來源查詢。
- **Security:** 發起分析仍需已啟用的 API key。
- **Compatibility:** 以代號發起分析的既有呼叫方式結果不變（美股查無此標的改為拒絕除外）。
- **Analytics / Tracking:** N/A

---

## 7. Dependencies & Risks

- **External Dependencies:** 證交所每日收盤行情（取代上市公司基本資料）、櫃買中心每日收盤行情、加密貨幣幣種清單、美股資料來源的代號查詢與名稱搜尋。
- **Known Risks:**
  - 每日收盤行情只列當天有交易的商品，當天暫停交易的股票會暫時無法辨識（反正也取不到收盤價）。
  - 美股名稱搜尋來源為非正式介面，可能變動；變動時退回「當代號照常分析」，不阻斷分析。
  - 加密貨幣幣種清單的名稱搜尋是模糊搜尋，部分符合易出現多個候選。
